# Stage 6 — 테스트와 QA

## 학습 목표

단위 테스트, 통합 테스트, 모의 API와 실제 API 검증의 차이를 설명한다.

## 개념 설명

단위 테스트는 함수 하나의 동작을 작은 입력으로 검사한다. 통합 테스트는 Git 수집에서 CLI 출력까지 이어지는 흐름을 검사한다. 모의(mock) API는 네트워크 대신 준비된 응답을 돌려주므로 키와 비용 없이 오류 상황을 반복 검사할 수 있다. 실제 API 검증은 공급자 서비스가 정말 같은 규격으로 작동하고 실제 AI 답변이 좋은지 확인한다. 모의 성공은 실제 연결 성공을 뜻하지 않는다.

## 동작 원리

```text
unittest discover → Git 임시 저장소/모의 HTTP 준비 → 기능 실행 → 요청 수·출력·오류 비교 → 통과/실패
```

## 실제 소스 해설

[`tests/test_git_collector.py`](../../tests/test_git_collector.py)는 임시 Git 저장소에서 미추적·스테이징·작업 트리를 검사한다. [`tests/test_ai_client.py`](../../tests/test_ai_client.py)는 JSON 요청, 파라미터, 인증·네트워크 오류를 모의한다. [`tests/test_drafts.py`](../../tests/test_drafts.py)는 형식과 보안을 검사한다. [`tests/test_cli.py`](../../tests/test_cli.py)는 명령에서 출력까지 이어지는 흐름과 API 호출 횟수를 확인한다. `unittest`는 Python 표준 테스트 모듈이며 `assertEqual`처럼 기대값을 비교한다.

## 실행 실습

Windows: `python -m unittest discover -s tests -v`.

macOS: `python3 -m unittest discover -s tests -v`.

실제 공급자 설정을 받았다면 README의 환경변수를 설정하고 실제 미커밋 변경이 있을 때 `commit`과 `pr`을 각각 한 번 실행한다. 요청마다 비용이 발생할 수 있으므로 중복 실행 전에 출력과 공급자 정책을 확인한다.

## 실행 결과

실제 확인: 현재 자동 테스트 13개 통과, 모의 네트워크 요청만 사용했다. 실제 코디세이 API는 키와 확인된 URL·모델이 없어 0회 요청, 연결·응답 품질은 미검증이다. 최신 결과와 추가 검증은 [QA 보고서](../../reports/QA.md)를 본다.

## 오류 사례

모의 응답의 `choices`가 비면 `APIError`가 난다. HTTP 401은 인증 실패로 처리된다. 테스트가 실패하면 고친 뒤 전체 스위트를 다시 실행해야 한다. 실제 API 장애와 코드 오류를 혼동하지 않도록 HTTP 상태와 재현 조건을 분리해 기록한다.

## 확인 문제

1. 모의 테스트가 실제 API 성공을 보장하나? **답:** 아니다. 네트워크·인증·공급자 호환성을 확인하지 못한다.
2. 통합 테스트의 목적은? **답:** 여러 모듈이 연결된 전체 흐름을 확인하는 것이다.
3. 요청 횟수 0인 경우는? **답:** 변경이 없거나 전송 전 검사에서 종료한 경우다.
